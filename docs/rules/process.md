# 过程整理规则

本文件是 `trace_viewer/analysis.py` 与过程界面的权威规则。版本 `rules-1`。读取、时间和原始会话统计沿用 [执行记录规则](records.md)。所有处理在本机以固定规则完成，无模型、联网、命令执行或关联文件读取。

## 从事件到卡片

- 每条归一化事件生成一张卡片，保留 `turnId`、`eventId`、原始记录序号及识别依据。未知类型保留为其他事件。
- 文件修改、网页、工具、子代理、上下文整理等先按源事件类型分类。命令优先采用记录的 `commandActions`；再对命令入口做有限的字面识别，不搜索输出或脚本正文来猜测执行用途。
- 可识别读取、搜索、列目录、unittest / pytest、npm / pnpm / yarn / bun test、cargo / go / dotnet test、Node 语法检查、compileall、包管理器构建。帮助和测试收集命令不计为测试调用。
- 支持常见 PowerShell / sh / bash 包装与多条命令；跳过 here-string 正文、注释和打印出来的示例。不是完整的 shell 解释器，不展开变量、不模拟条件分支、进程或文件系统。标签表示调用内容中可识别的命令用途，不证明复合命令的每个子命令都已经执行。
- 多用途命令保留所有识别标签；用于折叠阶段的主分类依次优先测试、检查、构建、读取、搜索、列目录，无法确定时为普通命令。
- 用户请求、公开摘要、进展说明和最终答复保留为陈述；计划、推测、结果措辞仅用开头的固定中英文规则标记。措辞标签不将陈述升级为已验证事实，用户请求与 Codex 陈述分别标注。

## 测试输出与异常

- 仅在识别出测试命令的事件中解析其返回输出。识别 unittest 的 `Ran N tests` 加 `OK / FAILED`、pytest 的终端汇总行；忽略 ANSI 颜色控制符。
- 命令退出 0 不生成“测试通过”。缺少可识别汇总显示退出码或“未识别测试汇总”。其他测试框架的命令可以识别，但汇总不推测。
- 同一事件有多个可识别报告时保留全部；任一报告失败，则此卡片的测试输出状态为失败。unittest 的跳过信息保留在原报告中；pytest 数量是报告条目的和，不能解释为不同测试用例数量。
- 显示“输出报告通过”，表示输出文本含相应格式，不能独立验证测试内容是否真实、是否覆盖需求。退出非零时同时保留整条命令退出码。
- 过程卡片的需查看标记包括基础事件异常和识别出的失败测试报告。顶部会话异常数继续遵循基础统计口径，因此可能与过程卡片的需查看数不同。

## 文件身份与关联

- 只使用源修改路径、`commandActions.path` 和受支持读取命令中的字面路径。保留原始路径供回查，身份键按记录的命令工作目录解析；没有命令目录时使用会话目录。
- Windows 路径统一分隔符、大小写与 `.` / `..`；POSIX 路径区分大小写。相同文件名位于不同目录时保持不同节点。不访问磁盘，不解析符号链接。
- 缺少可用绝对工作目录的相对路径，以及变量、通配符、计算表达式、`~`、盘符相对路径等不建立文件节点。识别到 `cd / Set-Location / pushd` 等改变目录的命令时，不关联该调用中的相对路径，不为其建立相同测试命令关系。
- `writes` 仅用于源状态为 `completed / applied` 且无错误的修改条目；其余为 `write_attempt`。这表示源日志的修改状态，不验证磁盘当前内容。

## 图结构与边

| 边 | 依据 | 含义 |
|---|---|---|
| contains | 会话、轮次与条目 ID | 记录的包含关系 |
| returns | 同一持久化条目的输出、返回或状态字段 | 本次调用的返回记录 |
| reads / targets | 字面路径或记录中的命令目标 | 读取指令或命令目标 |
| writes / write_attempt | 修改条目的路径、状态与错误字段 | 已完成修改记录或未确认完成的修改目标 |
| agent_reference | 记录明确提供的代理会话 ID | 关联子代理会话 |
| sequence | 同轮操作条目的记录序号 | 记录顺序，不表示完成先后或因果 |
| same_test_command | 同轮、相同字面测试参数序列及相同工作目录 | 测试命令再次出现；列出两次之间的修改条目 |

- 相同测试命令规则不推断两次运行的环境或文件内容相同，也不把中间修改解释为修复原因。未提供可解析目录时不建立该关系。不同测试参数、目录或轮次不合并。
- 不建立 supports、contradicts、causes、fixes 等语义关系，不计算能力评分。
- 节点和边 ID 由来源身份字段确定；追加事件不会改写已有 ID。图不会修改或覆盖原事件。

## 轮次汇总与界面

- 相邻、相同主阶段的操作合并展示。中间的自然语言说明不拆分阶段；说明与公开摘要可另外展开。轮次选择与“最新轮次”只定位视图。
- 操作数按事件条目计数，文件修改数按修改条目计数，测试调用数按包含测试命令的事件计数。读取 / 搜索 / 列目录 / 网页 / 图像为读取检索组；检查 / 构建为另一组；同一条目在一个组内仅计一次。复合命令可以属于多个组，各组数量不能简单相加为总操作数。
- 完成修改涉及文件数按本规则的规范化路径去重，顶部修改文件总数仍按原始路径去重；两个数字用途不同。未知命令单独提示，可回查完整原文。
- 通过、失败和未识别报告数量按测试调用条目计数，不是测试用例数量。
- 每个展开阶段先显示 50 步，可继续加载；关系图每页 12 步，每页最多 24 个关联对象，完整路径仍可在详情和对象筛选中查看。图中仅画当前范围内存在的边，跨页关系可以通过详情中的前后测试链接回查。
- 实线为日志字段关联，虚线区分记录顺序与字面规则匹配；连线可点击或通过键盘选中查看依据。文件节点筛选相应操作，动作及结果节点打开原始详情，代理节点尝试打开对应本地会话。

回归用例见 `tests/test_analysis.py`，API、私有内容省略及刷新联动见 `tests/test_history.py`。
